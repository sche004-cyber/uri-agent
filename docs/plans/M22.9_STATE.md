### What was built (scope: `uri_ui/` only, per plan §0.2/§4)

- **Branding (plan §3):** `applicationId` → `com.uriagent.dev` (`android/app/build.gradle.kts`, comment marks it explicitly non-publish-ready); `android:label` → `"URI — AI COMPANION"` (`AndroidManifest.xml`); `web/manifest.json` `name`/`short_name`/`description`/`background_color`/`theme_color` updated to the real theme tokens (`#FAF9F6` canvas / `#4A3AFF` accent, replacing Flutter's default `#0175C2`); `web/index.html` title/description/apple-mobile-web-app-title updated to match. The text wordmark is shown via the **pre-existing** `UriWordmark` widget (`lib/widgets/uri_wordmark.dart`, already used by the app-shell sidebar and About screen) — extended with a new opt-in `showTagline` parameter (default `false`, so every existing call site is visually unchanged) rather than replaced, after an implementation mistake (below) briefly overwrote it. `LoginScreen` and `OnboardingScreen` now show `UriWordmark(markSize: 40, showTagline: true)`, rendering "URI" + "— AI COMPANION". Launcher/web icons (5 Android densities, 4 web manifest icons, the web favicon) replaced with a generated, visually-neutral placeholder — a plain "U" monogram on a solid accent tile — so the app no longer ships Flutter's own default icon; not presented as final branding.
- **Durable session handling (plan §0.3/§3/§5.3):** confirmed via `auth_session.py`/`server.py` that no server-side token-refresh endpoint exists and `GET /auth/me` reports rejection as `{"authenticated": false}` at HTTP 200, never a 401 — so this stays client-side expiry *detection*, exactly as the plan required, not invented refresh. New `SessionStore` (`lib/services/session_store.dart`, same on-device `shared_preferences` pattern as `ServerAddressStore`) persists the bearer token/username on successful login/signup and clears them on logout. `UriClient` gained `authToken`, `restoreSession()`, and `validateSession()` (implemented in both `HttpUriClient` and `MockUriClient`); `AppState.loadPersistedSession()` (called from `main.dart` after the persisted server address is applied) restores a saved session optimistically, then proactively calls `validateSession()` — which clears local state and degrades honestly to logged-out only when the backend explicitly reports the token invalid, and never on a mere network failure (an unreachable backend returns `true`/unchanged, per §5.3's "never extend or invent trust" — and symmetrically, "can't confirm" must never be treated as "confirmed invalid" either). `UriApp` gained a `WidgetsBindingObserver` (`app.dart`) that calls `AppState.revalidateSession()` on `AppLifecycleState.resumed`, so a token that expires while the app is backgrounded — the actual mobile usage pattern §0.3 named — is caught the moment the app returns to the foreground rather than on the user's next action.
- **New tests:** `test/m22_9_durable_session_test.dart` (6 tests) — a session surviving a simulated relaunch, `logout` clearing the persisted session, an explicitly-rejected token degrading to logged-out on restore, an unreachable backend never forcing a logout, a rejected token also clearing in-memory conversation state, and the no-persisted-session no-op case.
- **`scripts/scan_apk_for_secrets.py`** (new, not shipped in the app) — a static scan of a built APK's assets/compiled Dart snapshot for key-shaped literals (named patterns for this project's actual provider key shapes are hard failures; a generic high-entropy pattern is reported separately as informational only, since build hashes/symbol tables trigger it constantly and would otherwise make the check useless noise).

### A mistake made and corrected during this same session, disclosed for transparency

While adding the wordmark, a `Write` call created `lib/widgets/uri_wordmark.dart` believing it to be a new file — it was not: a `UriWordmark` widget already existed there (committed in `HEAD`, used by `app_shell.dart`'s sidebar header and `about_settings_screen.dart`, with a `markSize`/`showWordmark` API), and the `Write` silently overwrote it. `flutter analyze` caught the resulting breakage immediately (`about_settings_screen.dart`/`app_shell.dart` calling named parameters that no longer existed) before anything was tested or committed. The original file was restored via `git checkout -- uri_ui/lib/widgets/uri_wordmark.dart`, re-read, and then extended in place (`showTagline`, default `false`) rather than replaced, so the pre-existing sidebar/About-screen usage is provably unchanged (`flutter analyze`/`flutter test` both confirm) and only the two new call sites (login, onboarding) opt into the fuller branded treatment.
