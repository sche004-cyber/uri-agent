## §5. Security Considerations

**5.1 — Zero embedded secrets in the built APK (the milestone's own named security requirement).** Verified by an automated static scan of the built APK's assets/compiled output for key-shaped string literals, run as part of this milestone's own test plan (§7) — not merely asserted.

**5.2 — TLS-only base URL once M22.3's TLS requirement is live.** The client's configured backend base URL must not silently permit a plaintext `http://` production endpoint; loopback/LAN development use (already the existing, correct M22.3 posture) is unaffected.

**5.3 — Durable-token handling must not weaken the existing session model.** Any client-side expiry-detection/refresh logic added here must not invent new trust (e.g., extending a session's effective lifetime beyond what the server-side `AuthSessionStore` actually still considers valid) — it is a UX improvement over the existing 401-then-logout behavior, not a new authority.
