## 5. Approved User Decisions

All seven decisions the prior draft flagged as open are now final. None is
treated as unresolved anywhere in this document.

### 5.1 Decision 1 — Five diagnostic GET endpoints stay PUBLIC
`/audit/shadow-comparison`, `/identity`, `/skills` (GET), `/capabilities`,
`/connections` (GET) remain **PUBLIC** in M22.3. M22.3's scope is not
expanded to reclassify them. They are explicitly marked **deferred** in the
route table (§4) for a later security/API-exposure milestone, not silently
dropped from consideration.

### 5.2 Decision 2 — Loopback-only default binding
The server binds to loopback (`127.0.0.1`/`::1`/`localhost`) **by default**.
Binding to any non-loopback host is refused unless **both** (a) TLS is
configured, **or** (b) an explicit `--allow-insecure-bind` override (or
equivalent `URI_ALLOW_INSECURE_BIND=1` env var) is supplied. Insecure LAN
exposure is **not** preserved as the default. See §6.7 and §19 for the
concrete, named operational consequence to `scripts/uri_server_ctl.ps1`.

### 5.3 Decision 3 — Raw uvicorn bypass accepted as a documented limitation
A direct `uvicorn uri_core.app.server:app --host 0.0.0.0` invocation
bypasses any guard placed in `scripts/run_uri_server.py`, because uvicorn's
CLI loader never gives the ASGI app a chance to see or reject its own bind
host. M22.3 does **not** attempt a global interception mechanism (e.g.
runtime self-inspection of the bound socket, wrapping uvicorn's `Config`
object) to close this. The **sanctioned launcher path is
`scripts/run_uri_server.py`**, and M22.3 protects exactly that path.
`server.py`'s own module docstring is updated to stop recommending the raw
CLI form and to point at the sanctioned launcher instead. This is documented
as an accepted operational limitation (§19), not an oversight.

### 5.4 Decision 4 — Rate limiting counts every attempt
The `/auth/login` and `/auth/signup` limiters count **every** request that
reaches the endpoint — successful or failed — not failures only. This is
the simpler, fail-closed counting basis: it cannot be evaded by an attacker
who interleaves guesses in a way that avoids triggering a failure-only
counter, at the cost of also counting a legitimate user's own repeated
correct logins toward the same window.

### 5.5 Decision 5 — Rate-limit thresholds
- `/auth/login`: **5 attempts / 60 seconds / client IP**
- `/auth/signup`: **3 attempts / 300 seconds / client IP**

Both thresholds are implemented as named, overridable configuration
constants (not hardcoded literals), so they can be retuned without a code
change to the limiter's logic itself.

### 5.6 Decision 6 — `/ask` request-size limit
- Maximum conversational text: **64 KB** (65,536 bytes), enforced as a
  Pydantic field constraint on `AskRequest.text`.
- The lower-level **Content-Length pre-check** proposed in the draft plan
  is retained in addition to the field constraint — the field constraint
  alone only rejects after the full body is already read into memory; the
  Content-Length check rejects before that, protecting against a payload
  large enough to cause memory pressure before Pydantic ever runs.

### 5.7 Decision 7 — CORS
- **Production:** explicit configured origins only, via
  `URI_CORS_ALLOWED_ORIGINS` (comma-separated exact origins).
- **Local development (no env var set):** loopback origins only, matched by
  an anchored regex (`localhost`/`127.0.0.1`, any port).
- **`allow_origins=["*"]` is never used**, in any configuration.

## 6. Proposed Architecture

### 6.1 Closing S1 — ADMIN gate
One new dependency, `_resolve_admin_principal`-equivalent, layered on the
existing `_resolve_principal` (which is unmodified):

```
resolve_admin_principal(principal: PrincipalContext = Depends(_resolve_principal)) -> PrincipalContext
    if principal.user_id is None: raise HTTPException(401)
    if principal.role != ROLE_ADMIN: raise HTTPException(403)
    return principal
```

Lives in a new, logic-only module, `uri_core/core/authorization.py` — not
in `principal_context.py` (a plain data shape by its own docstring) and not
inline in `server.py` (which is request/response plumbing only by its own
docstring). `server.py` adds only the `Depends(...)` wiring to the five S1
handlers, matching the existing precedent of
`_resolve_authenticated_user_id`/`_resolve_principal`.

### 6.2 Making classification enumerable
A new module, `uri_core/app/route_classification.py`, holds the exact table
in §4 as a plain `{(method, path): "PUBLIC" | "USER" | "ADMIN"}` mapping —
the single source of truth a developer edits when adding a route, and the
input to the route-enumeration test (§14.1) that fails if `len(app.routes)`
doesn't match the table's row count.

### 6.3 No new third-party dependency
Rate limiting, size limiting, and CORS allowlisting are all implemented
in-process with the standard library plus FastAPI's own
`CORSMiddleware` — no new package is added to `requirements.txt`, preserving
the ≤10-dependency portability ceiling.

### 6.4 Rate limiting (Decisions 4 and 5)
New module `uri_core/app/edge.py`: an in-process, fixed-window counter keyed
by client IP (`request.client.host`), counting every request per Decision 4,
evicting expired windows lazily. Exposed as a FastAPI dependency attached
only to `/auth/login` (5/60s) and `/auth/signup` (3/300s), both values
defined as named constants. Returns **429 with a `Retry-After` header** on
trip. State is process-memory (same risk class as the existing
`AuditTrail`), fails closed if internal state is ever unavailable, and
exposes a `reset()` hook so tests can clear it between cases (§14.6).

### 6.5 `/ask` request-size limit (Decision 6)
1. `AskRequest.text: str = Field(..., max_length=65536)` — the 64 KB
   conversational-text bound.
2. A Content-Length pre-check dependency scoped to `POST /ask` only (not
   global — `/files` already has its own independent `MAX_FILE_BYTES` cap
   and must not be double-capped), rejecting with 413 before the body is
   parsed.

### 6.6 CORS lockdown (Decision 7)
`server.py:541-546`'s `allow_origins=["*"]` is replaced with:
- `URI_CORS_ALLOWED_ORIGINS` env var (comma-separated exact origins) when
  set — the production path.
- Otherwise, `allow_origin_regex` anchored to loopback origins only
  (`^https?://(localhost|127\.0\.0\.1)(:\d+)?$`) — the local-dev default.
  This governs only browser-origin (Flutter web) callers; native
  Android/iOS/desktop HTTP clients do not send or enforce CORS at all, so
  the LAN-phone scenario in `server.py`'s own docstring is unaffected by
  this lockdown.
- No configuration path ever sets `allow_origins=["*"]`.

### 6.7 Loopback-only default binding with explicit override (Decisions 2 and 3)
In `scripts/run_uri_server.py`:
- Default `--host` changes to **`127.0.0.1`** (was `0.0.0.0`).
- Before calling `uvicorn.run(...)`: if the resolved host is not loopback
  **and** no TLS cert/key pair is configured **and** `--allow-insecure-bind`
  / `URI_ALLOW_INSECURE_BIND=1` is not present, refuse to start with a
  clear, actionable error (non-zero exit). If the override **is** present,
  proceed but log a loud, explicit warning naming exactly what was
  bypassed.
- `server.py`'s module docstring is updated to point at
  `python scripts/run_uri_server.py` (with the override or TLS flags as
  needed) as the sanctioned path, per Decision 3 — the raw `uvicorn` CLI
  form is no longer presented as guidance.
- **This is a breaking operational default change** for the existing
  persistent launcher — see §19 for the exact, named consequence and the
  required transition.

## 7. Security Invariants

1. Every entry in `app.routes` has a corresponding row in
   `route_classification.py`; an unclassified route fails the enumeration
   test (§14.1).
2. ADMIN gating is 401-then-403, never silently degraded: anonymous → 401,
   logged-in-non-admin → 403, never a 200, never a fallback to a
   legacy-ambient mode (the five S1 endpoints never had one).
3. No new authorization code reads `experience_tier` — only `role`.
   Extendable via the same AST-scan technique
   `test_experience_tier_never_authorizes.py` already uses.
4. The rate limiter fails closed: if its internal state is ever
   unavailable or corrupted, the dependency rejects the request rather than
   skipping the check.
5. The `/ask` size cap (Content-Length pre-check) is enforced before
   `UriOrchestrator.process_user_input` is ever called.
6. The CORS loopback regex is anchored (`^...$`) and cannot match
   `http://localhost.evil.com`-style suffix-abuse.
7. Non-loopback binding is refused by default; the override is explicit,
   logged, and never silently assumed.
8. No control introduced by this milestone sits inside the propose →
   validate → approve → execute chain; every change is at the HTTP edge,
   before or alongside existing `Depends(...)` resolution.
9. `experience_tier` remains strictly UX-only; the User's final authority,
   ADR-018, the Model↔Runtime Contract, and the AI Operating Policy are
   unaffected by any change in this milestone — none of this work touches
   model reasoning, approval, or capability execution.

## 19. Risks / Operational Considerations

1. **Named operational consequence of Decision 2 (loopback-only default):**
   `scripts/uri_server_ctl.ps1` currently invokes
   `python.exe scripts/run_uri_server.py` with **no host/port flags at
   all** (`uri_server_ctl.ps1:47`), which today resolves to
   `run_uri_server.py`'s existing `0.0.0.0` default. Once §6.7 ships and the
   default changes to `127.0.0.1`, **this persistent launcher will start
   binding loopback-only**, and any LAN/phone client that currently reaches
   the server via the host PC's LAN IP will stop being able to connect,
   unless the launcher's invocation is updated (Antigravity's A3, §12) to
   either (a) accept loopback-only operation until TLS/reverse-proxy exists
   (the safe default this plan recommends), or (b) explicitly pass
   `--allow-insecure-bind` with `--host 0.0.0.0`, accepting and logging the
   risk as a deliberate, visible choice. This is not a silent behavior
   change — A3 must make the launcher's resulting posture explicit in its
   own invocation, matching whichever of (a)/(b) reflects current
   operational need at implementation time.
2. **Decision 3's accepted limitation:** an operator who runs
   `uvicorn uri_core.app.server:app --host 0.0.0.0` directly, bypassing
   `scripts/run_uri_server.py`, is not stopped by this milestone's guard.
   This is a deliberate, documented scope boundary, not an oversight — the
   sanctioned launcher is the supported path, and `server.py`'s docstring
   is updated to say so.
3. **Rate limiting is per-IP only** — a distributed (many-IP) brute-force
   attack is not mitigated by this milestone's design. Noted so it is not
   later mistaken for a closed gap.
4. **Decision 4's every-attempt counting** means a legitimate user who
   mistypes their password and retries several times in quick succession
   can trip the same 429 a genuine attacker would. This is the accepted
   trade-off (simpler, fail-closed, harder to evade) versus a failure-only
   counter.
5. **Decision 1's deferred routes remain a real (low, but non-zero)
   disclosure surface** once any non-loopback exposure exists, even after
   this milestone. They are explicitly not closed here and must be
   revisited before any milestone that claims full remote-exposure
   readiness.
6. **S2/S3 (dynamic-import dispatcher; no per-user capability axis)** and
   API-key/secrets handling remain exactly as characterized in
   `URI_M22_ARCHITECTURE.md` §2 — closing S1/S5/S6 here does not clear any
   remote/mobile milestone on its own; M22.4/M22.5 remain required first.
