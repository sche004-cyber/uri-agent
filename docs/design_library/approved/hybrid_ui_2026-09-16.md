# Approved: URI Hybrid UI structure (Option D / "Hybrid")

**Date:** 2026-09-16
**Approved by:** User (direct instruction, live session: "Accept `READY_WITH_CHANGES`... Proceed directly to incorporate your findings and produce the Frozen UI Implementation Blueprint").
**Recorded by:** Claude, after independently reviewing Codex's 2026-09-15 planning draft and directly verifying the cited visual authority.

## What was decided

The concrete structure described as "Option D — Hybrid" in
`docs/design_library/UI_DIRECTION_OPTIONS.md` (drafted 2026-09-15) and
subsequently realized as a Claude Design canvas Artifact
(`https://claude.ai/artifact/FtXLngXPXiRMCY9YQBefht`, title "URI Hybrid
Design") is the approved structure for URI's Flutter UI:

- 5 top-level destinations: Home, Chat, Tasks, Connections & Providers, Settings.
- One collapsible sidebar (icon rail / icon+label expanded), persisted local preference.
- Home: a moderate tile-grid dashboard (**4 real tiles**, not the reference's 6 — see the exclusion below) plus a Suggested Actions / Needs Attention panel. No chat container or composer on Home.
- Chat: standalone workspace, own route, internal History tab, one composer with attachment/model-selector/mic/send.
- Tasks: filterable table (not cards, not a kanban board).
- Connections & Providers: one destination, two clearly labeled sections.
- Settings: nested sub-nav, ~8 remaining categories, Appearance (4 themes) included.
- Compact: a presentation-mode toggle within the same Chat/session state (not a separate screen/session).
- Mobile: 5-item bottom navigation (matches desktop destination set, "Connections & Providers" abbreviated to "Connect"); full real layouts exist in the reference only for Home and Chat.

## Why chosen over the alternatives

Option D (Hybrid) was the User's own explicit synthesis request after
reviewing Options A/B/C (see `UI_DIRECTION_OPTIONS.md` "Option D" intro) —
it resolves Option B's one open gap (Activity/History placement, folded
into a Chat "History" tab, same answer as Option C) and pairs Providers
with Connections on one destination rather than either omitting Providers
promotion (Option A) or giving it a fully separate top-level slot (Options
B/C), keeping the top-level destination count at 5 instead of 6.

## What was explicitly rejected as part of this approval

- **The reference's literal 6-tile Home grid.** Two of the six tiles
  rendered in `Main.dc.html` ("Upcoming Deadline", "Halted Workflows") have
  no real URI backend (no calendar capability; no global halted-workflow/
  project API) and are fabricated illustrative values in the mockup itself.
  Approved scope is the tile *component* and grid *layout*, not those two
  specific tiles' presence — see `UI_DESIGN_AUTHORITY.md`'s 2026-09-16
  correction for the full reasoning.
- **Treating the Mobile artboard as a complete 5-screen mobile spec.** Only
  Home and Chat are real mobile layouts in the reference; Tasks,
  Connections & Providers, and Settings are explicit placeholder cards
  there. This approval covers the Mobile Home/Chat layouts as reference-
  accurate and requires new responsive design (not reference adaptation)
  for the other three, per `docs/plans/UI_HYBRID_FROZEN_BLUEPRINT.md` Batch 4.
- **The reference's flat, always-enabled model-selector dropdown.** Visual
  position/trigger only; the actual selection behavior must be M31's real
  verified/unverified provider logic (`ChooseModelPopover`/
  `ModelSelectorChip`), not the mockup's decorative always-enabled list.
