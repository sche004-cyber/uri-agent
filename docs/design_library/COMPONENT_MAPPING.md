## Verified implementation hazards to cover in batches

1. `HttpUriClient.listTasks` (line 765) collapses network, HTTP and parse failures to `[]`; loadHomeSummary then renders zero. Connections has similar failure/empty concerns. Batch 1 must add client-side explicit load outcomes/status with tests, preserving wire contracts and existing caller compatibility. A global connectivity check alone cannot prove a particular resource fetch succeeded.
2. AppShell uses `KeyedSubtree(ValueKey(_index))`; UriCommandDock owns a TextEditingController. Batch 1 must preserve draft state when navigating; Batch 4 must prove the same for Compact transitions. Keep the shared controller/presentation state above disposable surfaces; no new state-management framework required.
3. `startNewChat` clears turns/attachments but does not explicitly reset conversationModelOverride; `resumeSession` sets session after await. Define/test per-session override/draft restoration and guard late responses before switching sessions; do not silently change global Brain. Navigation/Compact switching must never call startNewSession.
4. TaskItem has no completed status, due date or general-project lifecycle. Filter only actual fields; all returned rows are pending approvals. Do not invent backend work to match a reference table.
5. Old UriClient header claims no HTTP implementation; actual HttpUriClient and server handlers are authoritative evidence. This draft does not treat stale comments or prior passing reports as live verification.
