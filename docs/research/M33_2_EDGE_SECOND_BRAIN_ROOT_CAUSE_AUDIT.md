# M33.2 — Edge / Second Brain Foundation: Evidence & Root-Cause Audit

**Status:** FROZEN / IMPLEMENTATION-READY — Stage 1 evidence. No production code, runtime, model, or UI change is authorized by this document; M33.2 implementation has not started.

**Baseline inspected:** `631d630aa9f66b70142f55c7397995e9bafab70f` (`master == origin/master`, M33.1 CLOSED / ACCEPTED) on 2026-09-20. Unrelated uncommitted worktree artifacts are deliberately excluded and must not be used as M33.2 implementation evidence.

**Revision history:** revised 2026-09-20 after an independent plan review re-verified each claim below against live source. Corrections are applied in place and marked *[review 2026-09-20]*; the earlier wording is described rather than silently replaced. Final freeze audit 2026-09-20 revalidated the package against `631d630aa9f66b70142f55c7397995e9bafab70f` and corrected only stale baseline/governance references shared with the companion documents.

**Purpose:** establish the live seams and failure causes that make an optional, provider-agnostic Second Brain necessary and feasible without creating another authority path.

## 1. Root cause and product outcome

URI currently has a capable deterministic authority core and configurable Main-Brain provider routing, but its useful intelligence path is still predominantly a Main-Brain model call. A user with no configured/reachable Main Brain receives degraded behavior even though URI may already have a bounded capability that the deterministic runtime can authorize and execute. A large Main-Brain prompt also has avoidable cost/latency for simple classification, extraction, and low-risk replies.

M33.2 therefore introduces an *optional intelligence tier*, not an alternate URI system:

```text
URI_PREFLIGHT  deterministic URI control / known fast paths
EDGE           optional Second Brain proposals
MAIN_BRAIN     optional Main-Brain reasoning and model-native tools
```

*[review 2026-09-20 — naming correction.]* These three layers were originally written as "Tier 0 / Tier 1 / Tier 2". That vocabulary is already in live production use with incompatible meanings — `uri_core/core/native_tool_loop.py:1` defines Tier 0 as a Main-Brain chat that declined tools and Tier 1 as the native tool loop, `/ask` returns `"tier": "tier0"`/`"tier1"` envelope values (`:396-397,470,478,522`), and `uri_core/core/tool_schema.py:225` uses "Tier 2" for workflow-procedure escalation. The layer names above are used throughout M33.2 instead.

The target is to use the least expensive eligible layer while keeping URI useful when the Main Brain is absent. It is not to make a small model an authority, disguise a Main-Brain failure as a confident Edge answer, or reduce the Main-Brain path to a lowest-common-denominator interface.

## 3. Root causes and constraints proved by the live design

1. **Main-Brain availability is not guaranteed.** `ModelRouter` intentionally degrades after health/budget/fallback exhaustion. Its current default can also be locally unavailable when the configured model is not installed. The Edge layer must therefore have explicit no-Main-Brain behavior; it cannot silently fill every gap with a lower-quality answer.
2. **Capability discovery must be narrow.** URI already separates compact directory summaries from `describe()` detail. Feeding a full catalogue to a tiny model would duplicate existing progressive discovery and increase latency/error risk — and, per §2, the reused preselection primitive's own failure mode is exactly a full-catalogue fallback that Edge must override.
3. **The canonical path is safety-critical.** Native calls are translated before canonical execution; gates determine `READY`, permission denial, and approval requirements from runtime metadata. A direct Edge tool runner would bypass precisely the protection M32/M34 preserved.
4. **Current latency makes duplicate inference unacceptable.** M32's measured post-Batch-C analysis identified expensive repeated directory/context construction. An Edge pass must be selectively invoked, share the same per-turn turn-state/directory construction, and have URI_PREFLIGHT and explicit-Main bypasses. *[review 2026-09-20]* The shared artifact is the `build_turn_state_and_directory` result (`decision_engine.py:1029`), not a single shared capability projection: the Main-Brain native path deliberately offers the full catalogue (`tool_schema.py:214-226`) while Edge needs a bounded shortlist, so two distinct projections are derived from one shared construction.
5. **Existing persistence is user-scoped and portable by convention.** `user_scoped_path()` validates UUID user IDs (`portable_paths.py:47-64`) and provider/usage stores use atomic JSON/JSONL patterns. Edge preferences and telemetry must retain that isolation and cannot use `experience_tier` as a route/authority input.
6. **"Mode" is already an overloaded, partly authorization-relevant word.** *[review 2026-09-20 — new.]* URI carries capability mode `{office, diagnostic, admin}` on the principal (`config/modes.py:12,15`; `server.py:1346,1356`) and decision-contract mode (`decision_engine.py:73-81`), which governs executability. M33.2's routing preference must therefore be named `intelligence_mode` and must be provably unread by either path.

## 4. Candidate-runtime evidence (not commitments)

The focused primary-source evaluation is retained in `reports/Edge runtime evaluation.md` with underlying notes in `research_notes/Edge runtime evaluation/`.

- **Common vendor ownership, disclosed** *[review 2026-09-20 — new; an earlier draft presented these as two independent candidates].* Needle ships as the package `cactus-needle` 3.0.1 from `github.com/cactus-compute/needle` (`reports/Edge runtime evaluation.md:7`). Needle and Cactus are products of **one vendor**. Qualifying only those two cannot demonstrate that M33.2's contracts are vendor-agnostic, so an independent, non-Cactus-Compute local runtime is a mandatory benchmark control rather than an optional comparison.
- **Needle 3:** documented structured completion/function proposals and Windows x64/ARM64 distributions make it a candidate. Its `run()` loop executes supplied Python functions and is prohibited for URI. Its documented default-on telemetry (`NEEDLE_TELEMETRY=0`, `DO_NOT_TRACK=1` as opt-outs) and first-use artifact fetch mean offline/no-egress must be measured, not assumed. Only a `complete()`-style, proposal-only adapter can be evaluated.
- **Cactus:** documents text, vision, ASR, embeddings, local indexing and Android API 24+ arm64, but reviewed official sources do not establish Windows support, and Engine telemetry is described as opt-out without an identified disable mechanism. Bundle compatibility/conversion, cloud handoff/download behavior, telemetry, and local-only behavior remain acceptance gates. Cactus is a runtime candidate, never the definition of "Second Brain."
- **Licence** *[review 2026-09-20 — promoted from a passing mention to a stated blocking condition].* Cactus is "source-available under a license with use/funding/revenue restrictions, not a generally permissive open-source license" (`reports/Edge runtime evaluation.md:15`). A candidate whose licence does not permit URI's intended distribution and use is ineligible regardless of technical results, and licence review precedes benchmark investment.
- **Confidence:** vendor confidence is not a universal probability. Needle documents it as a calibrated-head/decode-probability minimum and returns `None` for fine-tuned weights whose calibration head was not updated (`reports/Edge runtime evaluation.md:7`), so `UNAVAILABLE` is an expected value rather than an error. Calibration is versioned evidence keyed by model/runtime/artifact/task slice. No source supports one fixed universal threshold or treating confidence as authorization.

## 5. Planning conclusions and stop conditions

1. M33.2 needs a provider-agnostic Edge contract, a runtime contract, and a deterministic routing policy **before** any vendor adapter is promoted.
2. The permanent per-user Edge Reply Confidence Threshold is a routing preference only. It must be live-updatable, persisted, visible to M33.3, and never writable by a model. Its comparison against a calibrated score must be defined once and explicitly, since the threshold is an integer percent and calibrated scores are floats.
3. Candidate adapters may run only in opt-in benchmark/experimental profiles until each tested platform/modality/artifact has passed proposal correctness, authority-boundary, adversarial-robustness, licence, resource, and network-silence gates.
4. Vision, voice, and structured extraction require sibling observation/transcription/extraction contracts. Full document reconstruction, graph writes, and UI redesign are later work.
5. Stop candidate promotion if any of the following is true: outbound traffic cannot be prevented/verified; artifact provenance is incomplete; confidence is missing/stale for direct reply; schema output is malformed; a capability cannot be short-listed safely; resource limits cannot be observed/enforced by the selected platform; the licence does not permit URI's intended use; an injected instruction in untrusted content can steer a proposal into execution; or an Edge result would require a relaxed approval/permission/evidence rule.

## 6. Open evidence to collect during implementation

- Frozen URI-owned text/action/extraction/vision/ASR workload and ground truth, per supported language/device slice.
- Cold/warm latency, TTFT, memory, CPU/GPU, disk/cache, battery/thermal where observable, and Main-Brain tokens avoided.
- Reliability curves and error slices for direct reply, intent, tool selection, arguments, structured extraction, and voice separately; no adaptive threshold release.
- Packet capture plus outbound-deny verification for normal, malformed, missing-artifact, timeout, and restart paths.
- **An adversarial corpus** *[review 2026-09-20 — restoring requirements already present in this audit's own evidence base but lost in the first distillation]*: prompt injection embedded in attachment, OCR, email and retrieved-document content; tool-schema injection; cross-user/tenant identifiers inside content; forged `cloud_handoff`, confidence and provenance metadata. Required pass condition: zero unauthorized execution and zero proposal outside the offered shortlist. See `research_notes/Edge runtime evaluation/needle.md:79` and `cactus.md:80`.
- **A licence and redistribution record per candidate**, collected before benchmark investment.
- Live end-to-end proof: no Main Brain configured → bounded command → Edge proposal → canonical validation/approval/dispatch/evidence; then complex request → explicit, model-authored limitation or clarification.
