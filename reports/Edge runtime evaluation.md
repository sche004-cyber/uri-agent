# Ground Edge Intelligence in URI Authority

M33.2 should treat Needle 3 and Cactus as optional, replaceable inference-adapter candidates rather than parts of URI's authority plane. **Needle 3 has documented Windows x64/ARM64 distribution and structured tool-proposal interfaces, but ships with default-on telemetry and first-use artifact fetch behavior; Cactus documents local text, vision, ASR, embeddings, and Android arm64, but the reviewed primary sources do not document Windows support or an Engine telemetry opt-out.** Neither candidate establishes URI workload quality, privacy, calibration, resource predictability, or safe execution. The implementation plan should therefore pin artifacts, make capability eligibility explicit, benchmark a URI-owned corpus on each real target, and require observed egress denial. Every model result—including calls, confidence, reasoning, embeddings, transcriptions, and cloud-handoff flags—remains an untrusted proposal that URI validates, authorizes, approves, executes, persists, audits, and feeds back through its canonical loop.

## Needle supplies proposals, not executable authority

**Source-supported facts.** `cactus-needle` 3.0.1 requires Python 3.9+ and only `huggingface_hub` as a base dependency; documented Python distributions cover Windows x64/ARM64 as well as macOS and Linux, while native folders and build paths span additional device targets ([package metadata](https://raw.githubusercontent.com/cactus-compute/needle/main/pyproject.toml); [supported devices](https://www.cactuscompute.com/blog/needle-supported-devices)). Its `complete()` response includes function calls, reasoning, confidence, throughput, and peak-RAM fields, and the vendor describes byte-level grammar-constrained call decoding ([API reference](https://github.com/cactus-compute/needle/blob/main/doc/apis.md); [README](https://github.com/cactus-compute/needle/blob/main/README.md)). Crucially, `run()` selects and executes supplied Python functions in its own agent loop, whereas `complete()` lets the host execute returned calls separately. Confidence is documented as a calibrated-head/decode-probability minimum; fine-tuned weights return `None` because their calibration head is not updated ([API reference](https://github.com/cactus-compute/needle/blob/main/doc/apis.md)). Binary telemetry is documented as enabled by default, with `NEEDLE_TELEMETRY=0` and `DO_NOT_TRACK=1` as opt-outs; first-use artifacts are fetched unless pre-provisioned ([project reference](https://github.com/cactus-compute/needle/blob/main/llms.txt); [offline guidance](https://github.com/cactus-compute/needle/blob/main/doc/apis.md)).

**URI recommendation.** Admit only an isolated `complete()`-style adapter: translate bounded returned calls into URI proposals, then run deterministic schema validation, route classification, tenant/role checks, approval, canonical execution, persistence, audit, and result feedback. Do not hand URI functions to `run()`, and do not use grammar validity, provider reasoning, confidence, or self-reported telemetry as evidence of authorization, policy compliance, or grounding. Pin the wheel, engine, weight/depth artifact, schemas, and SHA-256 manifest. Provision in a separate connected step; at runtime force offline artifact behavior, set both telemetry opt-outs, and enforce egress deny at the OS/process boundary. Acceptance evidence must show no DNS, TCP/UDP/QUIC, HTTP(S), model fetch, telemetry, crash-report, or retry attempts during normal, invalid, missing-artifact, load-failure, and restart paths. Vendor throughput and 8–29 MB binary claims are sizing hypotheses, not URI acceptance results ([README](https://github.com/cactus-compute/needle/blob/main/README.md)).

## Cactus broadens modalities but leaves Windows unproven

**Source-supported facts.** Cactus documents text completion/tool-call proposals, VLM image input, transcription and streaming transcription, text/image/audio embeddings, local RAG, and vector indexing; its supported-model material does not list text-to-speech ([supported models](https://docs.cactuscompute.com/v1.9/#supported-models); [Python API](https://docs.cactuscompute.com/latest/python/)). It accepts tool definitions and returns parsed function calls, and exposes C, Swift, Kotlin, Flutter, React Native, Python, and Rust bindings plus a loopback OpenAI-compatible HTTP server ([Engine API](https://github.com/cactus-compute/cactus/blob/main/docs/cactus_engine.md); [repository](https://github.com/cactus-compute/cactus)). Caller-supplied model paths support selecting already-compatible bundles, but Cactus uses an internal CQ weight format whose compatibility can change; generic Hugging Face conversion is labelled experimental and bundle generation for non-Cactus conversion is incomplete ([compatibility](https://docs.cactuscompute.com/v1.9/docs/compatibility/); [Engine API](https://github.com/cactus-compute/cactus/blob/main/docs/cactus_engine.md)). Android API 24+ arm64 is documented. The reviewed official materials list iOS, Android, macOS, and wearables but do **not** document a Windows binary, SDK, or support matrix ([Android documentation](https://docs.cactuscompute.com/v1.9/android/); [platform page](https://www.cactuscompute.com/engine)).

**Source-supported local-only constraints.** Missing bundles can trigger download/convert flows; automatic cloud handoff is configurable and completion surfaces `cloud_handoff`; Engine documentation says anonymous usage telemetry is opt-out but the reviewed material does not identify a disable mechanism ([Python downloads](https://docs.cactuscompute.com/latest/python/#model-downloads); [CLI server options](https://github.com/cactus-compute/cactus#using-this-repo); [Engine telemetry](https://github.com/cactus-compute/cactus/blob/main/docs/cactus_engine.md)). The runtime is source-available under a license with use/funding/revenue restrictions, not a generally permissive open-source license ([license](https://github.com/cactus-compute/cactus/blob/main/LICENSE)).

**URI recommendation.** Keep Cactus optional behind a provider contract rather than adopting its model or weight format as URI's canonical format. A candidate may be eligible only for the explicitly tested modality/model/platform tuple; do not claim Windows eligibility unless a supported Windows build, maintenance/support evidence, and full URI adapter evaluation exist. In a declared local-only profile, pre-provision verified artifacts, prohibit download/convert/auth paths, disable cloud handoff, omit credentials, and require outbound-deny capture. If Engine telemetry cannot be demonstrably disabled before traffic can occur, local-only acceptance fails. Cactus function calls, generated content, transcripts, embeddings, confidence, and cloud-handoff fields remain untrusted inputs; a loopback/OpenAI-compatible endpoint is an integration transport, never an authorization boundary.

## Calibration must be versioned evidence, never permission

**Source-supported facts.** Modern-network accuracy does not imply calibrated probabilities; temperature scaling fits a temperature on held-out validation data while weights remain fixed, and standard post-hoc calibration can degrade under distribution shift ([Guo et al.](https://proceedings.mlr.press/v70/guo17a.html); [Ovadia et al.](https://proceedings.neurips.cc/paper/2019/hash/8558cb408c1d76621371888657d2eb1d-Abstract.html)). NIST calls for representative tests, documented methodology, segment analysis where useful, and ongoing monitoring ([NIST AI RMF](https://nvlpubs.nist.gov/nistpubs/ai/nist.ai.100-1.pdf)). No source supports one universal threshold, ECE target, sample size, or scalar-confidence meaning across text generation, VLM, ASR, and retrieval.

**URI recommendation.** Calibrate and validate separately for each immutable model/tokenizer/preprocessor hash, quantization, runtime/provider/driver/OS, prompt/schema, task, and operating slice. Retain the split provenance and ID, ground truth/outcome, raw and calibrated score where available, abstain/fallback decision, predicted output, latency/resource trace, and error/shift slice; publish reliability diagrams with ECE, maximum calibration error, NLL, and task-quality metrics. Fit on a disjoint calibration split, then test representative stress slices: language, noisy audio, image quality/layout, document type, device/backend, and offline/resource pressure. URI may deterministically map calibrated uncertainty to clarification, review, abstention, or provenance; it must never map confidence to approval, execution, retry-around-policy, or elevated authority. Providers must declare score semantics and absence explicitly; URI must not fabricate comparable confidence.

## One frozen workload can test four capability classes

**Source-supported facts.** MLPerf Mobile treats preprocessing through postprocessing as one benchmarked execution and requires consistent systems/frameworks plus accuracy/performance evidence ([MLPerf rules](https://github.com/mlcommons/mobile_open/blob/main/rules/mobile_inference_rules.adoc)). Windows execution-provider availability and graph coverage depend on hardware, OS, drivers, and provider support ([Windows ML providers](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/supported-execution-providers)). MTEB spans eight embedding task types and 58 datasets; MME distinguishes multimodal perception and cognition; NIST OpenASR uses WER as primary ASR scoring, with CER relevant for some languages ([MTEB](https://arxiv.org/abs/2210.07316); [MME](https://arxiv.org/abs/2306.13394); [OpenASR plan](https://www.nist.gov/system/files/documents/2021/08/31/OpenASR21_EvalPlan_v1_3_1.pdf)). These are comparators and measurement models, not URI launch evidence.

**URI recommendation.** Freeze a versioned workload and full environment manifest: artifact, processor, quantization, prompt/schema, runtime/provider, OS/driver, device SKU, and power state. Run cold and warm separately and retain raw traces for end-to-end p50/p95/p99, TTFT or real-time factor, throughput, RSS/peak memory, disk/cache, failure/timeout, and platform-observable energy/thermal data. For text and structured extraction, score schema validity, required-field precision/recall/F1, exact/normalized values, hallucinated fields, appropriate abstention, and injection/paraphrase/long-context robustness. For vision, separate OCR/layout/perception from reasoning across images, screenshots, tables, blur, glare, rotation, crop, small text, multi-image, and ambiguity; use position-sensitivity checks rather than one free-form score ([MMBench](https://github.com/open-compass/MMBench); [DocVQA](https://arxiv.org/abs/2007.00398); [FUNSD](https://arxiv.org/abs/1905.13538)). For ASR, freeze normalization and score WER/CER plus error breakdown, streaming endpoint behavior, partial/final latency, and representative accents, noise, jargon, numbers, silence, overlap, and interruptions. For embeddings, measure recall@k, MRR, nDCG@k, similarity correlation, hard negatives, index build/update time, retrieval latency, and index resource cost. On Android, compare the selected delegate with CPU across multiple device/resource tiers; on Windows, record the actual provider and confirmed graph coverage. Never pool distinct device/backend results into a single “edge” score.

## Capability negotiation must fail closed under pressure

**Source-supported facts.** Android per-app heaps vary by device and pressure can produce thrashing, kills, or `OutOfMemoryError`; Windows provider availability and operator coverage remain backend-dependent ([Android memory overview](https://developer.android.com/topic/performance/memory-overview); [Windows ML WebGPU provider](https://learn.microsoft.com/en-us/windows/ai/new-windows-ml/webgpu-ep)). NIST requires evaluation against safety risks and safe failure outside knowledge limits ([NIST AI RMF](https://nvlpubs.nist.gov/nistpubs/ai/nist.ai.100-1.pdf)).

**URI recommendation.** M33.2 should define a signed/versioned descriptor containing only startup- and runtime-verifiable facts: operation/modality, schema and limits, supported languages, artifact IDs, score semantics, backends and known graph coverage, resource envelope, data-residency properties, and failure modes. Unknown, stale, or unverifiable means ineligible. The deterministic governor chooses only compatible verified routes; bounds deadline, cancellation, resource use, and retries; records degradation provenance; and returns defer, clarification, or an explicitly approved alternative. Preserve explicit non-claims: no guaranteed NPU/GPU, full-graph acceleration, fixed latency/memory/battery/thermal behavior, background survival, equivalent outputs across backends, calibrated/comparable confidence, modality/streaming/timestamp/embedding/offline support, or safe autonomous completion. Test missing provider, partial graph fallback, corruption, OOM/kill, timeout, offline, cancellation, malformed media, unsupported schemas/languages, low/unknown confidence, and repeat-run disagreement through the canonical loop.

## Conclusion

The practical architecture choice is a capability-negotiated adapter seam, not a runtime commitment. Needle is the stronger documented Windows proposal candidate but needs reproducible egress-silence and artifact-integrity proof; Cactus is a broader Android-oriented multimodal candidate but cannot satisfy a Windows or local-only claim from the reviewed sources. A vendor-neutral contract, pinned artifacts, URI-owned benchmark harness, and deterministic fail-closed governor preserve reversibility while turning each vendor claim into falsifiable acceptance evidence.

The decisive M33.2 deliverable is therefore not a model score. It is a reproducible evidence package showing that a specific candidate, artifact, configuration, device, and workload improves a declared user-facing task without receiving authority, leaking egress, or weakening URI's propose → validate → approve → execute chain.
